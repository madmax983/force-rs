# 🔭 Vantage: Spec for Bulk API PK Chunking Support

**Business problem:**
Extracting hundreds of millions of records using the standard Bulk API Query often fails due to Salesforce's 2-minute query timeout or 15-minute cursor timeout. Developers are forced to manually chunk data using Date/Time fields, which is inaccurate and complex.

**Gap Analysis:**
The Salesforce Bulk API supports "PK Chunking" (Primary Key Chunking) via the `Sforce-Enable-PKChunking` header, which automatically splits massive queries into manageable chunks based on the Record ID. Currently, our `force-rs` Bulk API implementation lacks native support and automated handling for these chunked batch results.

**Success metric:**
Success = Ability to automatically execute and process a 10-million record extraction using PK Chunking without hitting Salesforce timeouts, returning a unified stream of results.

👤 **User Story:**
As a Data Engineer, I want to use PK Chunking for my massive Bulk API queries, so that I can reliably extract hundreds of millions of records without timeout failures or manual data splitting.

✅ **Acceptance Criteria:**
- Must expose a configuration option on the Bulk Query builder.
- Must automatically append the `Sforce-Enable-PKChunking` header to the initial job request.
- Must manage the multiple batches generated by Salesforce (since PK chunking turns 1 batch into N batches).
- Must stream the results from all generated batches seamlessly to the caller.

🚫 **Out of Scope:**
- Automatic retry logic for failed individual chunks (Phase 2).
- PK Chunking for standard REST API queries (not supported by Salesforce).
